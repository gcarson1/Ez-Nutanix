# Decisions

Choices made where the brief left room, or where the brief and other inputs disagreed.

| # | Decision | Why |
|---|---|---|
| 1 | Purple slide look on top of the line-based design system: purple (`--ink`) is the structural color, plus a restrained status palette. | The master prompt asks for the slide's purple look; `DESIGN-SYSTEM.md` is monochrome. The original build's `tokens.css` had already merged them this way, so it was kept. |
| 2 | Preact (about 10 KB) for the UI. | Worth the bytes for a stateful, many-module UI; the build is still far under the 2 MB budget. |
| 3 | The whole scenario lives in the URL hash; cluster settings use shared keys (`src/state/scenario.ts`) across Protection & Capacity and Scale-out (Failure Gauntlet shares only RF). The Cluster & DSF Lab uses one fixed cluster and keeps only its scenario (`sc`) in the link. | A presenter can send a link to an exact configuration, and the top-bar presets load a cluster size into Protection & Capacity. |
| 4 | "Prism Federation" is presented as the slide's label for multi-Prism-Central federation under Nutanix Central, not as a product name. It opens the Nutanix Central module on its Federation tab. | No Nutanix product is called "Prism Federation" (docs/research/E-platform-services.md, 1d). |
| 5 | "Any Bare Metal Linux" opens Cloud Native AOS with the bare-metal target selected. | The brief maps it to 9.3. |
| 6 | Landing pane to module transition uses the View Transitions API (the clicked pane grows into the module header); browsers without it, and reduced motion, navigate without animation. | Spatial continuity without a dependency. |
| 7 | Presenter mode is a side drawer (P), not a second window. | Works when screen-sharing a single window; a second-window view can be added later. |
| 8 | Built file is not committed (`dist/` is ignored). CI builds it and uploads it as an artifact. | Keeps diffs reviewable; the deliverable is reproducible with `npm run build`. |
| 9 | The reference slide screenshot is not in the repo, so slide colors were not re-sampled (see design-tokens.md). | It was never added. |
| 10 | Facts that could not be verified are left out or shown with version-dependent wording rather than shipped as guesses. Details and sources are in `docs/facts.md`. | Brief, section 11. |
| 11 | Every module, the Cluster & DSF Lab included, offers preset choices above one picture that autoplays and loops with a scrub bar; most add a caption and a few key numbers. There are no step, Reset or speed controls, no Related boxes, and no screens that imitate Prism. | The owner asked for modules that read at a glance, presets instead of knobs, looping animations with scrubbing, and widgets that explain topics rather than demo the product. The audit is in the PR that made the change. |
| 12 | No module has an Honest fit ("Where this has trade-offs") callout. Trade-offs that matter stay in the presenter Q&A. | The owner asked to remove them all, overriding the master prompt's requirement for one per module. |
| 13 | The NCM Cost tab follows one project, dev-test, running hot, and shows how NCM brings it back under budget: a Cost Governance budget alert, its savings recommendations, then Self-Service quota, approval and scheduler policies. Each mechanism is checked in `docs/facts.md` section 6. | The owner found the old per-project showback, which only warned, understated how NCM prevents overspend. |
| 14 | Every looping animation pauses at the end of each step for a tenth of the loop's length, at least 0.4 s and at most 1 s. Data Lens always auto-blocks; the alert-only choice is gone. | The owner found the animations and captions moved too fast, and asked for a short delay after each step of no more than 1 s, and for Data Lens to show only auto-block. |
| 15 | The Cluster & DSF Lab is one fixed cluster (4 nodes, 4 VMs and 3 drives per node, RF2) with five scenarios chosen above the picture: data placement, live migration, planned shutdown, VM failover and drive failure. A one-line caption above the picture says what is happening; the right-hand pane explains the chosen scenario and does not change while it plays. The engine still decides the data layout, where HA restarts each VM and where each re-created copy lands; the lab only paces those results. | The owner asked for a set cluster size, obvious scenario buttons above the picture, no constantly updating right pane, and almost no customization. |
| 16 | Protection & Capacity has three tabs, like Cloud Manager: Copies (RF2, RF3; follows the shared node count and RF, so the top-bar presets size it), Erasure coding (one strip on 8 nodes, RF2 4/1 or RF3 4/2) and Blocks and racks (Node only, Block or Rack, on 8 nodes in 4 blocks or 12 nodes in 3 racks). Node only shows 1 of 8 pieces with both copies in one block, close to the 1-in-7 odds of random placement, so the risk is not exaggerated. The EC-X saving is shown three ways: copies only, an illustrative half-cold blend, and the all-cold theoretical maximum. | The simplified Cluster & DSF Lab no longer showed EC-X or block and rack awareness, so they moved here as presets. |
